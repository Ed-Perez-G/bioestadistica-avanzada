Manipulación de datos con dplyr y tidyr

1 Presentación

La manipulación de datos es una parte central de cualquier análisis estadístico. Muchos análisis requieren que antes de comenzar se deba importar, revisar, seleccionar, transformar, reorganizar y combinar información proveniente de una o varias bases de datos

Este es un documento introductorio de los paquetes dplyr y tidyr.

1.1 Objetivo de aprendizaje

Al finalizar la práctica, el estudiante será capaz de construir un flujo reproducible de manipulación de datos mediante dplyr y tidyr, incluyendo selección y filtrado de observaciones, creación y modificación de variables, resúmenes agrupados, transformación entre formatos ancho y largo, tratamiento explícito de valores faltantes y combinación de tablas mediante uniones.

4.1 Contar categorías

Otra forma de saber conocer una base de datos es contar categorias y hacer resumenes

participantes |>
  count(centro, sort = TRUE)
# A tibble: 3 × 2
  centro     n
  <chr>  <int>

2 Norte      4
3 Sur        4

Podemos contar combinaciones de categorías:

participantes |>
  count(centro, sexo, name = "n_participantes")
# A tibble: 6 × 3
  centro sexo   n_participantes
  <chr>  <chr>            <int>
1 Centro Hombre               2
2 Centro Mujer                2
3 Norte  Hombre               2
4 Norte  Mujer                2
5 Sur    Hombre               2
6 Sur    Mujer                2

La función count() equivale, de manera simplificada, a agrupar y resumir, este código produce el mismo resultado aunque utiliza diferentes funciones. Primero agrupa y luego resume:

participantes |>
  group_by(centro, sexo) |>
  summarise(n_participantes = n(), .groups = "drop") #.groups = "drop" remueve las agrupaciones
# A tibble: 6 × 3

14 Combinar bases de datos

Las uniones o joins permiten combinar tablas mediante una o más variables llave. Antes de unir tablas debemos responder:

  • ¿Cuál es la unidad de observación de cada tabla?
  • ¿Qué variable identifica de manera única cada fila?
  • ¿La relación esperada es uno a uno, uno a muchos o muchos a muchos?
  • ¿Qué registros deben conservarse?

14.8 Riesgo de multiplicar filas

Si una persona tiene varias filas en ambas tablas, una unión puede generar todas las combinaciones posibles.

tabla_a <- tibble(
  id = c("P001", "P001"),
  visita = c("basal", "mes_6")
)

tabla_b <- tibble(
  id = c("P001", "P001"),
  prueba = c("Glucosa", "Colesterol")
)

Unir solamente por id produciría cuatro filas para P001. Esto puede ser correcto si se desean todas las combinaciones, pero con frecuencia indica que la llave está incompleta. Antes y después de cada unión conviene comparar el número de filas y revisar la unicidad de las llaves.

16 Integrar un flujo completo

El siguiente ejemplo combina selección, filtrado, unión, creación de variables, agrupación y resumen.

resumen_baseline <- visitas |>
  filter(visita == "basal") |>
  left_join(
    participantes |>
      select(id, centro, sexo, estatura_cm),
    by = "id"
  ) |>
  left_join(
    laboratorio |>
      select(id, glucosa_mg_dl, colesterol_mg_dl),
    by = "id"
  ) |>
  mutate(
    estatura_m = estatura_cm / 100,
    imc = peso_kg / estatura_m^2,
    glucosa_elevada = case_when(
      is.na(glucosa_mg_dl) ~ NA_character_,
      glucosa_mg_dl >= 126 ~ "Sí",
      TRUE ~ "No"
    )
  ) |>
  group_by(centro) |>
  summarise(
    n = n(),
    imc_medio = mean(imc, na.rm = TRUE),
    glucosa_media = mean(glucosa_mg_dl, na.rm = TRUE),
    glucosa_elevada_n = sum(glucosa_elevada == "Sí", na.rm = TRUE),
    .groups = "drop"
  )

19 Errores frecuentes

  • Modificar manualmente el archivo original en lugar de registrar la transformación mediante código.
  • Utilizar rutas absolutas que solamente funcionan en una computadora.
  • Confundir select(), que trabaja con columnas, con filter(), que trabaja con filas.
  • Escribir variable == NA en lugar de is.na(variable).
  • Olvidar na.rm = TRUE sin investigar primero por qué existen valores faltantes.
  • Convertir variables numéricas en texto durante una limpieza.
  • Hacer una unión sin comprobar la unicidad de las llaves.
  • Perder participantes inadvertidamente mediante inner_join().
  • Multiplicar filas mediante una relación muchos a muchos no prevista.
  • Usar pivot_wider() sin comprobar que cada combinación de llaves identifica un solo valor.
  • Sobrescribir una variable sin documentar la transformación.
  • Generar una tabla final sin explicar su unidad de observación.
