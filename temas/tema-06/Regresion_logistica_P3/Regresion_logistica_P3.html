6. Evaluación y diagnóstico del modelo

6.1 Supuestos y condiciones de la regresión logística

Condición ¿Cómo se evalúa?
Desenlace binario codificado 0/1 Diseño
Independencia de las observaciones Diseño (en genética: sin parientes ni relación críptica)
Linealidad entre predictores continuos y el logit Gráfico de logit empírico, términos no lineales + LRT
Ausencia de multicolinealidad check_collinearity() (VIF)
Sin separación completa o cuasicompleta Tablas cruzadas, coeficientes y EE enormes
Sin observaciones excesivamente influyentes check_outliers() (distancia de Cook)
Tamaño de muestra suficiente (≈ 10 EPV) Conteo de eventos / parámetros

No se requiere normalidad de residuos ni homocedasticidad, a diferencia de la regresión lineal (Hosmer, Lemeshow, y Sturdivant 2013; Pérez Guerrero 2024).

Panorama general con check_model()

check_model(m_final)

Panorama general con check_model()

¿Cómo leer check_model() en regresión logística?

  • Posterior predictive check: las predicciones del modelo deben reproducir la proporción observada de 0 y 1.
  • Binned residuals: residuos promedio por grupos de probabilidad predicha; ≈ 95 % deben caer dentro de las bandas de error (Gelman y Hill 2007).
  • Influential observations: puntos fuera de las líneas de contorno de Cook son influyentes.
  • Collinearity: VIF de cada predictor.
  • Uniformity of residuals: residuos cuantílicos simulados; deben seguir la diagonal.

Cada panel se revisa a detalle en las siguientes diapositivas (Lüdecke et al. 2021).

6.4 Separación completa y cuasicompleta

Ocurre cuando un predictor (o combinación) separa perfectamente casos de controles (Heinze y Schemper 2002).

table(Variante_rara = datos$var_rara, Caso = datos$caso)
             Caso
Variante_rara   0   1
            0 400 393
            1   0   7
m_sep <- glm(caso ~ var_rara + dosis_T + sexo + edad + tabaquismo + PC1,
             data = datos, family = binomial)
summary(m_sep)$coefficients["var_rara", ]
  Estimate Std. Error    z value   Pr(>|z|) 
   16.8739   516.0436     0.0327     0.9739
  • Todos los portadores de la variante rara son casos (celda con 0) → el OR “tiende a infinito”.
  • Señales: β enormes (> 10), EE gigantes, p ≈ 1, advertencia “fitted probabilities numerically 0 or 1”.
  • Cuasicompleta: separación casi perfecta (típica del modelo recesivo con alelos raros).

¿Qué hacer ante separación?

  1. No eliminar la variable solo por eso: es probablemente un efecto fuerte.
  2. Regresión logística penalizada de Firth: estimaciones finitas y con menor sesgo en muestras pequeñas (Firth 1993; Heinze y Schemper 2002).
  3. Agrupar categorías raras (p. ej., modelo dominante en lugar de genotípico), regresión logística exacta o métodos bayesianos.
# install.packages("logistf")
library(logistf)
m_firth <- logistf(caso ~ var_rara + dosis_T + sexo + edad + tabaquismo + PC1, data = datos)
summary(m_firth)   # OR finito con IC por verosimilitud perfilada penalizada

6.5 Residuos agrupados (binned residuals)

residuos_agrupados <- binned_residuals(m_final)
residuos_agrupados
Warning: About 86% of the residuals are inside the error bounds (~95% or higher would be good).
plot(residuos_agrupados)

Interpretación de los residuos agrupados

  • Con un desenlace 0/1, los residuos individuales no son informativos; se agrupan por probabilidad predicha (Gelman y Hill 2007; Lüdecke et al. 2021).
  • Aquí ≈ 86 % de los grupos cae dentro de las bandas (lo ideal es ≥ 95 %): señal de desajuste moderado.
  • ¿Por qué? Sabemos cómo se simularon los datos: el modelo omite predictores reales (SNP03, SNP11, la variante rara y la interacción G × E).

Un diagnóstico “imperfecto” no invalida automáticamente el OR del SNP, pero obliga a investigar: ¿variables omitidas?, ¿términos no lineales?, ¿interacciones?

6.7 Comparación de modelos: AIC y BIC

\[AIC = -2\ln L + 2k \qquad BIC = -2\ln L + k\ln(n)\]

datos$dominante <- ifelse(datos$dosis_T >= 1, 1, 0)
datos$recesivo  <- ifelse(datos$dosis_T == 2, 1, 0)
m_dom <- glm(caso ~ dominante + sexo + edad + tabaquismo + PC1, data = datos, family = binomial)
m_rec <- glm(caso ~ recesivo  + sexo + edad + tabaquismo + PC1, data = datos, family = binomial)
m_gen <- glm(caso ~ rs7574865 + sexo + edad + tabaquismo + PC1, data = datos, family = binomial)

compare_performance(m_final, m_dom, m_rec, m_gen, metrics = c("AIC", "BIC", "R2"))

  • Menor AIC/BIC = mejor balance entre ajuste y complejidad. Diferencias < 2 son poco relevantes (Burnham y Anderson 2002).
  • BIC penaliza más los parámetros (favorece modelos simples). Sirven también para modelos no anidados.
  • \(R^2\) en logística: pseudo-\(R^2\) (Tjur, Nagelkerke); no se interpretan como en regresión lineal (Tjur 2009).

7.1 Probabilidades predichas

datos$prob <- predict(m_final, type = "response")

# Dos perfiles: mujer de 55 años, fumadora actual, PC1 = 0, con GG o TT
perfiles <- data.frame(dosis_T = c(0, 2), sexo = "Mujer", edad = 55,
                       tabaquismo = "Actual", PC1 = 0)
predict(m_final, newdata = perfiles, type = "response")
     1      2 
0.5593 0.7313

En casos y controles (50 % casos por diseño) estas probabilidades no son riesgos reales. Si se conoce la prevalencia (π), se corrige el intercepto: \(\beta_0^* = \beta_0 + \ln\frac{\pi}{1-\pi} - \ln\frac{\bar y}{1-\bar y}\) (King y Zeng 2001).

prevalencia <- 0.015                                   # prevalencia poblacional (simulada)
logit_muestra <- predict(m_final, newdata = perfiles)  # escala logit
plogis(logit_muestra + log(prevalencia / (1 - prevalencia)) - log(0.5 / 0.5))
      1       2 
0.01896 0.03979

7.3 Sensibilidad, especificidad y valores predictivos

VP <- matriz["1", "1"]; FP <- matriz["1", "0"]
FN <- matriz["0", "1"]; VN <- matriz["0", "0"]

sensibilidad  <- VP / (VP + FN)   # casos correctamente identificados
especificidad <- VN / (VN + FP)   # controles correctamente identificados
VPP <- VP / (VP + FP)             # de los clasificados como caso, ¿cuántos lo son?
VPN <- VN / (VN + FN)
round(c(sensibilidad = sensibilidad, especificidad = especificidad, VPP = VPP, VPN = VPN), 3)
 sensibilidad especificidad           VPP           VPN 
        0.708         0.690         0.695         0.702

Los valores predictivos dependen de la prevalencia

# VPP en la población real (teorema de Bayes), prevalencia de AR = 1.5 %
prev <- 0.015
VPP_poblacion <- (sensibilidad * prev) / (sensibilidad * prev + (1 - especificidad) * (1 - prev))
round(VPP_poblacion, 3)
[1] 0.034

En la muestra (50 % casos) el VPP es 0.7; en la población (1.5 % de AR) baja a 0.034. La mayoría de los “positivos” serían falsos positivos. Sensibilidad y especificidad no dependen de la prevalencia; VPP y VPN sí.

Prueba de Hosmer–Lemeshow

performance_hosmer(m_final, n_bins = 10)
# Hosmer-Lemeshow Goodness-of-Fit Test

  Chi-squared: 11.745
           df:  8    
      p-value:  0.163
  • p > 0.05 → no hay evidencia de mal ajuste (Hosmer, Lemeshow, y Sturdivant 2013).
  • Limitaciones: depende del número de grupos, tiene poca potencia en muestras pequeñas y casi siempre es significativa en muestras muy grandes. Prefiera el gráfico de calibración (Van Calster et al. 2019).
  • Discriminación (AUC) y calibración son propiedades distintas: un modelo puede ordenar bien a los pacientes y aun así dar probabilidades erróneas.

Validación interna: validación cruzada de 10 pliegues

auc_cv <- function(formula, datos, k = 10) {
  set.seed(123)
  pliegue <- sample(rep(1:k, length.out = nrow(datos)))   # asigna cada persona a un pliegue
  prob_cv <- rep(NA, nrow(datos))
  for (i in 1:k) {
    m_i <- glm(formula, data = datos[pliegue != i, ], family = binomial)          # entrena sin el pliegue i
    prob_cv[pliegue == i] <- predict(m_i, newdata = datos[pliegue == i, ], type = "response")  # predice el pliegue i
  }
  as.numeric(auc(datos$caso, prob_cv, quiet = TRUE))
}
c(AUC_cv_final = auc_cv(formula(m_final), datos), AUC_cv_inflado = auc_cv(f_inflado, datos))
  AUC_cv_final AUC_cv_inflado 
        0.7536         0.7594

La ventaja aparente del modelo inflado se reduce casi por completo al validar: la mayor parte era ruido. Lo poco que conserva proviene de SNP03 y SNP11, los únicos SNPs del panel con efecto real en la simulación.

  • Explicar y predecir son objetivos distintos que llevan a modelos distintos (Shmueli 2010).
  • rs7574865 puede ser un marcador en desequilibrio de ligamiento con la variante causal; la causalidad requiere replicación, mapeo fino y evidencia funcional.

8.4 Errores frecuentes de interpretación

  1. Interpretar el OR como RR (“el doble de riesgo”) cuando el evento es frecuente (Celis de la Rosa y Labrada Martagón 2014).
  2. Interpretar el OR como probabilidad (“1.46 = 46 % de probabilidad”) (Sperandei 2014).
  3. “p > 0.05 → no hay efecto” (ver G × E en la Parte 2) (Wasserstein y Lazar 2016).
  4. Reportar probabilidades absolutas de un estudio de casos y controles sin corregir.
  5. Interpretar los OR de las covariables de ajuste como efectos causales (falacia de la Tabla 2) (Westreich y Greenland 2013).
  6. Probar muchos SNPs o modelos de herencia sin corregir comparaciones múltiples.
  7. Selección automática stepwise y reportar el modelo como si fuera pre-especificado (Heinze, Wallisch, y Dunkler 2018).
  8. Ignorar la separación y reportar OR = 21 000 000.
  9. Confundir asociación significativa con utilidad clínica para predecir (Ranganathan, Pramesh, y Aggarwal 2017).

8.5 Limitaciones metodológicas y estadísticas

  • Diseño: casos y controles → sesgo de selección y de memoria (tabaquismo); no estima riesgos absolutos.
  • Medición: errores de genotipificación (revisar HWE), clasificación del desenlace.
  • Confusión residual: un solo PC puede no capturar toda la estructura poblacional.
  • Potencia: insuficiente para interacciones y variantes raras.
  • Generalización: frecuencias alélicas y efectos pueden variar entre poblaciones.
  • Modelo: linealidad en el logit, variables omitidas (binned residuals), sobreajuste.
  • Datos faltantes: el análisis de casos completos puede sesgar los OR (ver Tema 2).

Para estudios de asociación genética, la guía STREGA indica qué reportar: genotipificación, HWE, estratificación, modelo genético y comparaciones múltiples (Little et al. 2009).

Cierre

Respuesta a la pregunta guía

¿Cómo podemos determinar si una variante genética está asociada con una enfermedad, cuantificar esa asociación y evaluar si nuestras conclusiones son estadísticamente válidas?

Pregunta Herramienta Resultado en nuestro estudio
¿Está asociada? Regresión logística + LRT, corrección por comparaciones múltiples Sí: p (LRT) = 0.0012
¿Cuánto? OR ajustado + IC 95 % (aditivo) OR = 1.46 (1.16–1.85); verdadero = 1.30
¿Es válido? Ajuste por ancestría, linealidad, VIF, separación, residuos, influyentes Confusión por ancestría corregida; residuos sugieren predictores omitidos
¿Predice? AUC, calibración, validación cruzada Discrimina poco por sí solo (AUC = 0.62)

Mensajes clave

  1. Diagnostique antes de interpretar: linealidad en el logit, colinealidad, separación, influyentes y residuos agrupados.
  2. Compare modelos anidados con LRT y no anidados con AIC/BIC.
  3. Discriminación (AUC) y calibración son cosas distintas; ambas se validan fuera de la muestra de entrenamiento.
  4. En casos y controles, VPP y probabilidades dependen de la prevalencia.
  5. Un SNP puede estar asociado y ser un mal predictor: asociación ≠ predicción ≠ causalidad.
  6. Comunique con tablas OR (IC 95 %), forest plots y las guías STREGA/TRIPOD.
